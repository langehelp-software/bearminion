Content types: declare a blog, a news list or a fixed page in the content model, and get entries with their own fields, a sort order, a paginated listing page and lists in the editor. Guide: [Content types](https://docs.bearminion.com/content-types/). A site that declares no types builds the same HTML as before with the files it has.

- **The home page is a fixed page.** "Home page" is gone from the page form, and so are `POST /pages/:slug/set-home` and `previousHomeSlug` in `POST /save`. No page can be renamed to `index`. Nothing in your content changes: `content/pages/index.json` is still the home page. To change what visitors see first, edit the home page's sections. If you really want another page's content there, swap the two files in git and set each file's `slug`.
- **Content types in the editor API.** `types: defineTypes({ blog: multi({ path: '/blog/{slug}', fields, sort, listing }), about: single({ path: '/about' }) })` in the content model declares the site's own types next to the built-in home page, 404 page and `pages`. New routes: `GET /types`, `/types/:id/entries` (list, create, read, save, rename, delete), `/types/:id/listing` and `/types/:id/document`. `/pages` works as before. Deleting an image or video now also checks entries, listing pages and singles, and a page cannot take a slug that is the address of a type.
- **Migrations are told the type.** A `ContentMigration` receives the content type's id as a third argument. Existing migrations need no change.
- **Routing for types.** `siteRoutes(model, content)` lists every address of the site with what it shows (pages, singles, entries, and each listing page with its entries and pagination), `findRoute` picks one, and the hosted editor's `content.getRoute(pathname)` answers the same for one address from the repository. `loadContent()` also returns `entries`, `listings` and `singles`, and `contentCollections()` returns the extra collections under `types`. A site without `types` gets what it got before: two collections, the same pages.
- **The starter publishes declared types.** `src/pages/[...slug].astro` draws pages, entries, singles and listing pages from one route list, with two new components for a listing: `EntryList.astro` (a card per entry: title, and `date`, `excerpt` and `cover` when the type has fields by those names) and `Pagination.astro`. Listing page 2 and later is at `/blog/page/2`, has its own title and canonical address, and is in the sitemap. An entry whose `draft` field is on shows in `astro dev` and is left out of a build. A site without types builds the same HTML as before.
- **A build says when the site's files are too old for its types.** A site that declares a type but still has the route file from before content types fails `astro build` with the list of addresses that were not written and the fix (`npx bearminion add types`); `astro dev` warns. A site that declares no types is never checked.
- **`npx bearminion add types`** updates the files of a site made before 1.21 to the ones that publish content types: the page route, the collections, the content readers and the two listing components. Files you did not change are replaced, files you changed stop the command, and your `astro.config.ts` and content model are never edited. Only a site that declares a type needs it.
- **Content types in the editor.** Each declared type has its own list under Pages, in its sort order, with a New entry form; a title is enough to create an entry, and a required date starts as today. An entry opens at its own address. Its fields (date, excerpt, cover, a switch, a choice, a list) are edited in a Fields group drawn from the type's schema, and the section picker offers only the sections the type allows. Listing pages and singles are listed and edited like pages, with a fixed address. Links to entries are offered in the link picker and checked like links to pages. Drafts, undo and saved versions are kept per document.
- **`npx bearminion add type`** declares a content type. In a terminal it asks for the id, many entries or one page, the address, the fields (text, paragraph, date, number, switch, choice, image, list), a listing page and the order; scripts and assistants pass `--kind`, `--path`, `--label`, `--field name:kind`, `--sort` and `--listing` instead. Each type is its own file in `src/lib/types/`, gathered by `src/lib/types/index.ts` and passed to the content model as `types: siteTypes`, so a second and third type are a new file and one line each. It checks the type as `astro dev` would, and that no page or other type has its address, before writing anything, and it updates the site's own files like `add types`. **`npx bearminion add blog`** is `add type` with the blog answered: posts at `/blog/<slug>` with a date, an excerpt, a cover and a draft switch, newest first, listed at `/blog`. A new site starts with pages only.
